# ТЗ следующему участнику: настоящая коллекция MovieMind

## Перед началом

Продолжать от готовой ветки `yarik`, а не от пустой `main`. Перенести её файлы в свою ветку по командному порядку. Сначала открыть все пять страниц. Сохранить оформление, рабочие фильтры, описание фильма и список «Посмотреть позже».

## Цель

Заменить демонстрационные записи реальным каталогом из 500–1000 уникальных фильмов. В этом этапе сделать качество данных и проверяемый импорт; авторизацию, сервер и очередной редизайн не добавлять.

## 1. Источник и импорт

1. Выбрать легально доступный источник метаданных, описать условия использования и атрибуцию в `DATA_SOURCES.md`. Если источник требует ключ, держать его в локальном окружении, не в клиентском коде или GitHub.
2. Добавить воспроизводимый скрипт импорта с инструкцией запуска. Итоговые данные должны работать статически, без запроса к API из браузера.
3. Собрать 500–1000 уникальных записей. Удалять дубли по внешнему идентификатору; отдельно проверять одинаковые название + год. Не генерировать вымышленные факты для заполнения пустых полей.
4. Сохранить стабильность `id`: удалить/переименовать старые демо-ID осознанно, чтобы сохранённые списки не стали указывать на другие фильмы. При смене набора данных повысить версию ключа localStorage или выполнить описанную миграцию.

## 2. Контракт записи

Сохранить текущие поля: `id` (целое), `title`, `year`, `genres` (строка через `;`), `mood` (целое 1–10, необязательно), `rating` (0–10, необязательно), `description`, `posterUrl` (необязательно).

Добавить при наличии: `externalId`, `originalTitle`, `countries`, `durationMinutes`, `ratingSource`. У отсутствующих сведений оставлять пустое значение/отсутствующее поле; не подменять неизвестный рейтинг нулём. Описать все поля и диапазоны в `DATA_SOURCES.md`.

Настроение не брать из несуществующего поля API. Выбрать воспроизводимое правило по жанрам или размечать вручную, указав метод. Если данных нет — оставлять `mood` пустым; существующий фильтр уже исключает такие фильмы при ограничении диапазона.

## 3. Постеры и источники просмотра

- Использовать изображения только при разрешённом использовании, хранить необходимые сведения об атрибуции. Не маскировать концептуальную SVG-афишу под официальный постер.
- Сделать устойчивую заглушку при отсутствии картинки и при сетевой ошибке.
- Удалить `example.com` и неподтверждённые ссылки из `availability.js`. Вносить только точную проверенную страницу фильма на легальном сервисе, дату и статус; если проверки нет — честно показать «Сведения о доступности не найдены».
- Отметки о демо-данных убирать только после фактической замены коллекции и тестовых источников. Сохранить атрибуцию рейтингов.

## 4. Интерфейс и производительность

- Проверить пагинацию «Показать ещё» на 24/48/последней странице; не выводить все 1000 карточек сразу.
- На главной заменить жёстко заданный фильм и счётчик `01 / 12` данными из коллекции, обновить тексты демо-коллекции.
- Проверить поиск кириллицей/латиницей, сортировку, комбинированные фильтры, пустую выдачу, возврат из рекомендаций с сохранением параметров и сохранённый список после перезагрузки.
- Сохранить работу без сборки и без сторонних шрифтов. Проверить ширины 360, 768 и 1440 px.

## Критерии приёмки

- В каталоге 500–1000 уникальных настоящих фильмов, счётчик соответствует данным.
- Есть скрипт импорта и документ с источниками, лицензиями, схемой, датой выгрузки и методом разметки настроения.
- Проверка данных ловит повторяющиеся ID, неправильные диапазоны рейтинга/настроения, некорректные годы и опасные URL.
- Для неизвестных данных и отсутствующих постеров нет ошибок и выдуманных значений.
- Поиск, все фильтры, сортировка, подбор, пагинация и список проходят перечисленные сценарии; в консоли нет ошибок.
- В репозитории нет ключей, токенов, `node_modules` и личных файлов.
- В конце обновить README: что сделано, как проверено, известные ограничения; написать `NEXT_TASK.md` для следующего участника и загрузить всё в свою ветку. Слияние в main согласовать внутри команды отдельно.
